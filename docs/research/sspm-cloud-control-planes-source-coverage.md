# SSPM cloud rows: organization and service control-plane coverage

Reviewed 2026-11-27. Okta ISPM's [integration inventory](https://help.okta.com/ispm/en-us/content/topics/ispm/guides.htm) describes visibility and recommendations with provider-specific scope. It is not evidence of full workload hardening or target-side write coverage. These four guides use customer-operated, narrowly scoped provider surfaces and do not require ISPM.

| Exact platform | Provider and connector evidence | Verified offline pack scope | Separate or unverified |
|---|---|---|---|
| AWS | [Okta AWS integration](https://help.okta.com/ispm/en-us/content/topics/ispm/aws.htm), [Organizations trusted access](https://docs.aws.amazon.com/organizations/latest/userguide/orgs_integrate_services.html), [organization trails](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/creating-trail-organization.html) | Commercial expected organization ID and all-features mode plus bounded SCP catalog. | No CloudFormation deployment; trust and delegated admin, SCP ancestry and CloudTrail delivery need review. Workforce IAM Identity Center and Bedrock are distinct products/scopes. |
| Google Cloud | [Okta Google Cloud integration](https://help.okta.com/ispm/en-us/content/topics/ispm/google-cloud-platform.htm), [organization baseline](https://docs.cloud.google.com/resource-manager/docs/manage-baseline-constraints), [organization policy](https://docs.cloud.google.com/organization-policy/create-organization-policies) | Expected project ancestry and two effective managed service-account key guardrail rules. | Conditional evaluation, explicitly existing credentials, Google Workspace, Vertex AI and workload safeguards are separate. |
| Microsoft Azure | [Okta Azure integration](https://help.okta.com/ispm/en-us/content/topics/ispm/microsoft-azure.htm), [ARM management groups](https://learn.microsoft.com/en-us/azure/governance/management-groups/manage), [policy assignment CLI](https://learn.microsoft.com/en-us/cli/azure/policy/assignment?view=azure-cli-latest) | Commercial tenant verification and explicit management-group/ancestor policy assignment inventory. | Entra and Power BI are separate; does not validate policy effects, exemptions, compliance or operation of a collector. |
| Microsoft Foundry | [Keyless authentication](https://learn.microsoft.com/en-us/azure/ai-services/disable-local-auth), [account ARM template](https://learn.microsoft.com/en-us/azure/ai-foundry/concepts/encryption-keys-portal), [agent networking](https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/networking-options) | Exact AIServices account and reported ARM local-auth/public-access flags. | No distinct Okta ISPM Foundry connector verified in the integration inventory; management-plane visibility is not data-plane enforcement, project RBAC, egress or connected-service assurance. |
