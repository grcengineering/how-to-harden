# SSPM coverage: Sumo Logic, Coralogix, Cribl Cloud and Dynatrace SaaS

Source and scope review: 2026-11-27. The SSPM inventory identifies vendor candidates, not proof of the connector's privileges or the product editions it supports.

| Product | Evidence-backed scope | Open boundaries |
|---------|-----------------------|-----------------|
| Sumo Logic | Hosted tenant: [SAML lockdown](https://www.sumologic.com/help/Manage/Security/SAML/01-Set-Up-SAML-for-Single-Sign-On/), [network access](https://www.sumologic.com/help/docs/manage/security/create-allowlist-ip-cidr-addresses/), and [separate audit indexes](https://www.sumologic.com/help/docs/manage/security/audit-indexes/). | Collector registration, Cloud SIEM and anonymous dashboard access are independent controls. Neither the allowlist flags nor audit setting attest observed outcome. |
| Coralogix | Commercial team's [four login-control surfaces and permissions](https://coralogix.com/docs/user-guides/account-management/user-management/login-access-policy/) and [API-key control modes](https://coralogix.com/docs/user-guides/account-management/api-keys/api-keys/). | SaaS login rules do not restrict service-to-service OAuth clients. Empty allowlists do not enforce a restriction. The representative guide does not configure BYOC, government, audit export or data-plane encryption. |
| Cribl Cloud | Commercial hosted organization only: [permission inheritance](https://docs.cribl.io/iam/permissions/), [SSO mappings](https://docs.cribl.io/iam/4.19/sso-cloud/), [API credentials](https://docs.cribl.io/cribl-as-code/api-auth/), and [identity events](https://docs.cribl.io/iam/cloud-identity-event-logs/). | Do not apply the commercial endpoint and IP allowlist guidance to Government. Data-plane pipeline and customer-managed Leader hardening are not covered by these controls. |
| Dynatrace SaaS | [Account Management](https://docs.dynatrace.com/docs/manage/account-management) identity, groups and OAuth, with [account audit evidence](https://docs.dynatrace.com/docs/manage/account-management/audit-logs). | Managed/on-prem, environment access tokens, configuration audit on Grail, and account versus environment role combinations are separate areas. |

## Automation surfaces

| Surface | Sumo Logic | Coralogix | Cribl Cloud | Dynatrace SaaS |
|---------|------------|-----------|-------------|---------------|
| REST | The [OpenAPI schema](https://api.sumologic.com/docs/sumologic-api.yaml) documents distinct login/content flags and a separate audit-policy boolean. Both GETs are packed. | Official [V5 IP management API](https://coralogix.com/docs/api-reference/v5/ip-access-service/get-company-ip-access-settings/) and IAM tooling are documented. CLI is provided here; HTTP request authentication handling was not independently tested. | [Management API list credentials](https://docs.cribl.io/cribl-as-code/api-reference/management-plane/) is packed and bound to the returned organization. The vendor’s [generated response models](https://github.com/criblio/cribl_cloud_management_sdk_python/tree/main/src/cribl_mgmt_plane/models) define the count, credential roles and CIDR fields. Do not call the product-specific workspace endpoint for this account inventory. | [Group list](https://docs.dynatrace.com/docs/dynatrace-api/account-management-api/group-management-api/get-all-groups) is packed; [account audit](https://docs.dynatrace.com/docs/dynatrace-api/account-management-api/account-audits-api/get-account-audits) exists, but archive export is not included. |
| CLI | Vendor collector installer is not a tenant-admin CLI; no verified command for these settings. | [Official cx](https://coralogix.com/docs/external/cx-cli/documents/command-reference/) has scoped IP and group reads; explicit profile required. | Bundled [Stream CLI](https://docs.cribl.io/stream/4.16/cli-reference/) is not the Cloud organization administration interface. | [dtctl](https://docs.dynatrace.com/docs/platform/dtctl) targets environment/direct resource operations; [Monaco](https://docs.dynatrace.com/docs/deliver/configuration-as-code/monaco/monaco-api-support-and-access-handling) covers some IAM-policy configuration, not a verified equivalent for these account reads. |
| Terraform | [Vendor provider workflow](https://www.sumologic.com/help/docs/api/about-apis/terraform-with-sumo-logic/) is documented; its audit policy example uses a separate HTTP provider, not an independently verified native resource. | [Vendor provider](https://github.com/coralogix/terraform-provider-coralogix) includes identity and access features; resource/data source parity for these controls is not independently tested in this tranche. | [Vendor provider](https://github.com/criblio/terraform-provider-criblio) includes cloud workspace management; credentials resource/data source coverage not tested. | [Official Terraform provider inventory](https://github.com/dynatrace-oss/terraform-provider-dynatrace/blob/main/documentation/supported-resources.md) lists IAM group/policy resources; only the REST read is included here. |
| SDK | [Vendor Go SDK](https://github.com/SumoLogic/sumologic-go-sdk) exists; no generated client included. | Management SDK operations not independently validated; use packaged CLI or API documentation. | [Management SDK](https://github.com/criblio/cribl_cloud_management_sdk_python/) is Preview; no dependency required by these packs. | Account operations are documented as REST; no supported equivalent client operation bundled. |
| Native config | Collector installation arguments do not set account policy. | Ingestion settings or local CLI config do not prove team-side enforcement. | Self-managed files do not describe Cloud organization policy. | Monaco deployment descriptors, where supported, are distinct from account SSO. |
| SIEM | Audit Index and Audit Event Index differ in format, edition and enablement. | Tenant log export/detection contract not verified in this tranche. | Identity events can be forwarded from Enterprise to a secured destination. | Account, classic environment, and Grail audit records must be evaluated independently. |

The public CIS selection did not surface product-specific benchmarks. The CISA SCuBA baseline is not used for these scopes. No DISA STIG or product-specific NIST/NSA/ACSC settings baseline was verified. No incident or vendor certification was used as a substitute for the actual customer-facing settings.

## Validation

- The Jekyll preview generated all four guide pages, each with three profile controls, the cheat-sheet panel and the expected rendered Code Pack links. No hosted site or browser session was exercised.
- HTH guide validation and the isolated four-vendor pack validation passed with zero warnings. All six scripts have v1 contracts; six of twelve controls have linked packs. ShellCheck and all seven offline fixture tests passed.
- The fixture tests cover tenant/pod binding, CLI profile scoping, disabled flags, typed responses and failure paths without falling back to a live network call. Scoped Gitleaks reported no leaks; scoped OpenGrep reported no findings under the available repository rules. The Aikido MCP was not available. No tenant access, credential issuance, or configuration mutation was performed.
