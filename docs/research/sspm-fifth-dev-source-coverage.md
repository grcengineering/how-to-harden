# SSPM survey crosswalk: Anodot and Epic Systems

## Anodot: scoped monitoring guide

[Reco's public integration catalog](https://www.reco.ai/integrations?29e8e612_page=1&e8f6d276_page=2) names Anodot without identifying a product edition. The guide covers the hosted Business Monitoring and Anomaly Detection platform acquired by [Glassbox](https://www.glassbox.com/news/glassbox-anodot-acquisition/), for which Glassbox still publishes [service-specific terms](https://www.glassbox.com/terms-conditions-anodot/). It does not cover the separate cloud cost management offering grouped into Umbrella in [Anodot's company-issued statement](https://www.prnewswire.com/news-releases/anodot-forms-umbrella-business-unit-to-focus-on-cloud-cost-management-offering-302417568.html) or the separate Glassbox-native admin console. The catalog does not establish Reco's edition support or write-back capabilities.

- The public [Anodot URL documentation](https://support.anodot.com/docs/login-and-api-urls) lists one-label account subdomains and legacy regional hosts under `anodot.com`. The packs accept only this HTTPS host pattern, never follow redirects, and take an existing authorized API bearer token. They neither acquire refresh tokens nor use a Data Collection Key.
- The [Anodot published user operation](https://support.anodot.com/reference/create-group) has a misleading page slug; the title, GET path and response sample explicitly show `GET /api/v2/users`. The table describes an enum while the response sample shows an array. The sample also represents organization IDs with 24 hexadecimal characters despite the table's UUID label, so the pack validates shape and exact equality to the approved ID rather than assuming a UUID. Unknown role labels are counted for review rather than treated as ordinary users. No raw identities are emitted.
- The [channel API](https://support.anodot.com/reference/get-channels) documents `GET /api/v2/channels` and channel type records. The pack reports counts only, not destination names, configuration or whether the requesting token can see every channel. Verify actual destination ownership and group restrictions in the admin UI and connected systems.
- [Anodot's Snowflake source documentation](https://support.anodot.com/docs/snowflake) and [credential update guidance](https://support.anodot.com/docs/updating-source-credentials-for-existing-sources) distinguish API/ingestion credentials from upstream database credentials. The guide does not automate changing a source, revoking keys, or touching live data.

## Epic Systems: clarification and source material required

[Valence's public application catalog](https://www.valencesecurity.com/saas-application-security) lists Epic Systems under IT & IAM, but does not specify the Epic product, module, hosting model, release, or admin surface. Epic's [public ONC certification exhibit](https://www.epic.com/mu/) confirms some supported security capabilities and distinguishes Hyperspace, EpicCare Link, MyChart and other products; it is not a configuration guide and directs version-specific questions to Galaxy or the Epic representative. Epic's [contact page](https://userweb.epic.com/contact/) describes UserWeb as its setup/support documentation portal, and [UserWeb](https://userweb.epic.com/) requires sign-in. Its public [developer resources](https://open.epic.com/DeveloperResources) and [client ID tutorial](https://open.epic.com/Tech/GetTechSpec?spec=Client+ID+tutorial.pdf) describe interface and application registration, not a clinical tenant's account security or configuration APIs. Do not use a clinical API as a stand-in for the missing administrative interface.

For an Epic guide, first confirm the intended Epic product/module, hosting model and release, and obtain shareable, vendor-authoritative documentation for customer controls and the associated configuration/validation steps. A Code Pack additionally needs a verified administrative or evidence-export interface and a synthetic fixture. No broad Epic guide or pack was created; no Epic tenant access was attempted.
