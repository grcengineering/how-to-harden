# SSPM survey crosswalk: application and data platforms

The SSPM survey identifies candidate platform names; vendor administration sources, not survey rows, substantiate customer-manageable settings. This crosswalk addresses edition scope and the narrower evidence returned by each Code Pack. It does not verify SSPM integration, write-back, tenant access or commercial availability on every plan.

## Evidence and verification boundaries

- **Aptible:** [Endpoint filtering](https://www.aptible.com/docs/core-concepts/apps/connecting-to-apps/app-endpoints/ip-filtering) documents a per-endpoint IPv4 allowlist and its limits. [Official CLI synopsis](https://www.aptible.com/docs/reference/aptible-cli/cli-commands/cli-endpoints-list) supplies the exact command, app and environment selectors, and fields. CLI output may contain private endpoint metadata; the pack does not infer compliance or touch application payloads. [Aptible's security FAQ](https://www.aptible.com/platform/security) documents owner exemptions and SSO bypass controls.
- **Capella:** [Operational Management API](https://production.docs.couchbase.com/cloud/management-api-reference/index.html) documents project-viewer permissions for `GET .../allowedcidrs` and `GET .../auditLog`, and a per-cluster ceiling of 75 allowed CIDRs. The network pack rejects a count mismatch and never follows server-supplied pagination links. The audit pack accepts the documented nested event ID shape and reports only the number of excluded users. [Key administration](https://docs.couchbase.com/cloud/management-api-guide/management-api-start.html) documents key expiry, scoping and IP restrictions for the management token, separate from database ingress. [Audit documentation](https://docs.couchbase.com/cloud/security/audit-management.html) limits cluster auditing to Enterprise.
- **Redis Cloud:** [API base and authentication](https://redis.io/docs/latest/operate/rc/api/get-started/use-rest-api/) and [key authentication](https://redis.io/docs/latest/operate/rc/api/get-started/) document the fixed HTTPS destination and both credential headers. Redis's Go client confirms the [Pro request](https://github.com/RedisLabs/rediscloud-go-api/blob/v0.52.1/service/databases/service.go), [Essentials request](https://github.com/RedisLabs/rediscloud-go-api/blob/v0.52.1/service/fixed/databases/service.go), and the response fields in the [Pro model](https://github.com/RedisLabs/rediscloud-go-api/blob/v0.52.1/service/databases/model.go) and [Essentials model](https://pkg.go.dev/github.com/RedisLabs/rediscloud-go-api@v0.52.1/service/fixed/databases#Security). Only selected fields are output, never credentials or full responses. The vendor SDK treats Essentials security properties as potentially undocumented, so an absent TLS field fails explicitly and absent source IP metadata is labeled not-reported.
- **Alteryx:** [Alteryx One API guide](https://help.alteryx.com/aac/en/developer-help/get-started-with-alteryx-one-apis.html) and its [public sample response](https://help.alteryx.com/developer-help/fr/get-started-with-alteryx-one-apis.html) document US1, bearer authentication and the user's own `GET /v4/apiAccessTokens` metadata. Evidence is only response count and timestamps, not identifiers or all-workspace coverage. [Workspace sign-in](https://help.alteryx.com/platform/en/admin/admin-reference/admin-console/single-sign-on.html) and [account audit behavior](https://help.alteryx.com/aac/en/platform/admin/admin-reference/account-management/audit-logs-page.html) are different scopes. The user's current region and entitlement govern availability.

No authenticated tenant calls, writes, or live click-path checks were performed. The tests use synthetic responses and mock vendor calls.
