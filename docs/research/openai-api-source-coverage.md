# OpenAI API Platform source coverage

Started 2026-11-05 **before control design**. Scope: customer-controlled API organization/project access and developer integration boundaries, including hosted Agents, tool connections, all indexed model-family APIs, state and delivery callbacks. Baseline: no separate API Platform guide or API pack directory existed. Family/common controls and ownership are reconciled in the [OpenAI family ledger](openai-source-coverage.md). Placement: OpenAI → API Platform; API projects do not inherit ChatGPT workspace authorization.

No tenants declared — Tier 0+1 only. No credential reads, credential creation, live model requests or tenant configuration took place. Guide maturity remains `ai-drafted` with zero live-validation marks.

Private `.hth-validation/openai-api-sources/manifest.json` retains URL, UTC time, status, length and SHA-256; at the API checkpoint it contained 104 successful fetches and three failed guessed routes across API and adjacent developer products. Retrieval counts are not coverage percentages. GitHub raw bodies that stalled were fetched from the official GitHub contents API and base64-decoded, without third-party reconstruction.

The initial candidates were RBAC, key governance, endpoint retention, signed callbacks, indexed Agents/tool security branches, Administration endpoints, changelog/deprecations, and adjacent Ads/SIWC/plugin/commerce products. Selecting controls followed those reads. This is their final reconciliation, including older omissions.

**Daybreak correction, before control 5.4 design:** a second index reconciliation found that the initial pass had read but failed to disposition the index's Daybreak branch. Successfully fetched the complete [Responses Daybreak guide](https://developers.openai.com/api/docs/guides/daybreak), [cybersecurity checks](https://developers.openai.com/api/docs/guides/safety-checks/cybersecurity), [PSP setup/operations](https://developers.openai.com/api/docs/guides/private-safety-processing), [tool review](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals), and native project retrieve/modify references. ## Validation and limits

- **PASS:** `bun test scripts/test-openai-api-refresh.test.ts` — 16 tests / 110 assertions with the isolated actual SDK 7.51.0: webhook freshness/signatures/durable retry; hosted/Daybreak native serialization and explicit selection/no fallback; MCP constraints; complete paginated export; key visibility; ingress; two-store inventory and PSP saved status. Transport fixtures verify secret-free argv, quoted stdin credentials, curlrc suppression, fixed origins/explicit loopback, private-file permissions/cleanup, late-page zero-output failure, raw-error omission and oversized-body refusal.
- **PASS:** `bun install --cwd packs/openai-api/sdk --frozen-lockfile --ignore-scripts`. Tests import the installed SDK from this exact directory. No ambient root dependency or root manifest/lockfile changes are required.
- **PASS:** official provider 1.5.0 `terraform init -backend=false -input=false`, `terraform validate`, `terraform providers schema -json`; `terraform fmt -check packs/openai-api/terraform`. No plan/apply or API authentication. Sandbox escalation enabled only the local provider socket and loopback tests.
- Structural/generated/site integration is the family lane's final gate; this child task does not mutate shared generated files or Git metadata.
- **DRIFT-CHECKED-ONLY:** public implementation paths. **VERIFIED-LIVE: 0**. Console steps, eligibility, WIF exchange, network/certificate/private-link enforcement, actual SDK execution, callback deployment, SIEM mapping and endpoint deletion were not tenant-tested.
- Daybreak project toggle fields remain unverified in the inspected project retrieve/modify references and provider schema; documented console setup is retained. The current API model table does not specify Terra's exact explicit program value, so the guide does not infer it from Red approval. Saved PSP `validated` is not continuous health, and a GET does not perform validation. Cloud storage/EKM, enabled policy, per-user enforcement and actual streaming `cyber_policy` handling require authorized integration validation.
- No product-specific CIS/STIG/SCuBA setting identifiers or vulnerability claims published. No third-party source was required for these interface omissions. An unresearched external baseline is not asserted absent.
- Failed guesses `/api/docs/guides/security.md`, `/api/docs/guides/cli.md`, `/plugins/security-privacy.md` returned generic 404 shells. Real indexes supplied API replacements and plugin auth. These failures establish no feature absence; broader plugin/commerce coverage is reconciled by family lane.

Final API/provider/CLI retrieval subset: **100 successful first-party bodies**, including full indexes and the official provider/CLI references; four additional current Help pages verify Daybreak overview/onboarding/setup/troubleshooting. Adjacent Ads, SIWC, plugin and commerce bodies are excluded from that subset.
