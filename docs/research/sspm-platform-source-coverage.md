# Initial source coverage for Confluent Cloud, Contentful, Freshdesk, and Anypoint

Verified 2026-11-27 against the linked first-party documentation. This is an initial customer-side configuration set, not certification or exhaustive administration coverage. No tenant access, live changes, or customer data were used.

| Product | Candidate coverage and separation | Scope exclusions |
|---------|-----------------------------------|------------------|
| Confluent Cloud (IBM) | [Security FAQ](https://docs.confluent.io/cloud/current/security/security-faq.html) distinguishes Cloud IAM and network filtering; service account permissions, IP filters and audit event coverage are in the guide. | Self-managed platform is not Cloud. Kafka ACLs, private network setup, external IdP mapping and encryption options are expansion candidates. |
| Contentful (Salesforce) | [Trust Center](https://trust.contentful.com/updates) establishes acquisition closure, not administrative controls. The guide uses the organization role, SAML and audit export documentation. [SCIM user reference](https://www.contentful.com/developers/docs/references/scim-api/users/) separates provisioning from role changes. | Content Delivery and Preview API permissions, webhooks, and tenant-specific token policies require separate controls. |
| Freshdesk (Freshworks) | Product support portal documents agent access, role and scope, Enterprise IP restrictions and audit events. Neo Admin Center is the identity plane. | Freshservice is a separate product. Freshdesk Omni and legacy plans can have different menus and capabilities. |
| MuleSoft Anypoint (Salesforce) | [Access Management](https://docs.mulesoft.com/access-management/) and its associated configuration manuals establish root IdP, business-group authority, Connected Apps and audit boundaries. | No PCE, runtime gateway or deployment configuration coverage. A client list is not a Connected App scope attestation. |

## Automation census

| Surface | Confluent Cloud | Contentful | Freshdesk | Anypoint |
|---------|-----------------|------------|-----------|----------|
| REST | IAM service-account list packed; documented create supported; network and RBAC endpoints not packaged. | User Management memberships packed; SCIM provisioning and role write are distinct; no SSO write asserted. | Agents list packed; admin reads and agent assignment updates are documented. No audit-export or Neo settings API asserted. | Access Management client listing and Audit Log Query documented; not packaged without a verified response contract or reviewed export setup. |
| GraphQL | No IAM GraphQL handle identified in the public Cloud API reference reviewed. | GraphQL Content API is a separate delivery plane; no organization admin claim. | No relevant handle identified in the public product API. | No relevant Access Management GraphQL handle verified. |
| First-party CLI | `confluent` identity listing packed; more IAM/network commands documented. | `contentful` organization SSO verification packed; not an IdP MFA audit. | `fdk` covers development, not Freshdesk tenant administration. | 4.x account plugin environment list packed; documented connected app auth. |
| Terraform | Dedicated service-account resource packed; bindings intentionally separate. | No supported Terraform identity operation verified for the lifecycle covered here. | No supported agent role or tenant IP resource verified. | New internal environment-scoped Connected App resource packed; refresh, imports and other resources out of this first slice. |
| SDK/config | No separate pack verified for these specific controls. | Delivery/development libraries do not imply organization admin support. | FDK apps and code examples do not imply a tenant-native admin SDK or config. | No separate SDK or file-based identity configuration verified for these controls. |
| SIEM | Audit stream/event categories documented. | Customer storage delivery documented; Enterprise stream uses OCSF. | Audit viewing documented, public export not verified. | Telemetry Exporter documented, with subscription limits. |

A bounded search of the [CIS Benchmarks catalog](https://www.cisecurity.org/cis-benchmarks) and [CIS DISA STIG index](https://www.cisecurity.org/benchmark/stig_bm) did not identify a directly applicable named benchmark for these four SaaS surfaces. The [CISA SCuBA materials](https://www.cisa.gov/scuba) describe Microsoft 365 and Google Workspace baselines; do not apply them to these products by inference. Product-specific private Trust Center material was not reviewed, and public assurance attestations were not used as settings evidence. No SIEM package is claimed without a reviewed ingestion schema and endpoint-native test. Edition, group visibility, and caller authorization are prerequisites, not verified tenant settings.
