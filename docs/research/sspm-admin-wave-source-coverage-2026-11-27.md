# SSPM source reconciliation: customer administration and audit

Reviewed 2026-11-27. These narrow management-plane controls do not imply feature parity with SSPM connectors. No live tenant or credential was used, and no endpoint starting a scan, submitting a test payload, writing settings, sending notices or contacting third parties was used or shipped.

| Source label | HTH scope | First-party evidence | Pack boundary |
|---|---|---|---|
| HackerOne | Customer bug bounty or vulnerability disclosure program and organization, not researcher workflows or pentest-specific admin | [Organization permissions](https://docs.hackerone.com/en/articles/9095492-permissions), [SAML](https://docs.hackerone.com/en/articles/8487039-single-sign-on-sso-via-saml), [membership API](https://api.hackerone.com/customer-resources/#programs-get-program-members) | One human program membership page; does not enumerate individual identifiers, engagement reports, effective group permissions or organization-wide membership |
| Bright Security | Bright cloud organization, credential scope, project visibility and audit; not target registration, scan management or vulnerability testing | [Organization controls](https://docs.brightsec.com/docs/manage-your-organization), [SAML](https://docs.brightsec.com/docs/saml-sso), [project REST list](https://docs.brightsec.com/docs/integrating-with-the-bright-api), [default API host](https://docs.brightsec.com/docs/cli-configuration-files) | Counts projects from the first returned page only. No findings, hosts, entry points, scans, target validation or mutations |
| Envoy | Hosted workplace tenant with Envoy Visitors; not Envoy Proxy or hardware access | [Roles](https://envoy.help/en/articles/6778712-admin-roles-permissions), [SAML with global admin exception](https://envoy.help/en/articles/3450163-setting-up-saml), [retention](https://envoy.help/en/articles/12356182-data-retention-policy), [locations API](https://developers.envoy.com/hub/reference/locations-1), [location response example](https://developers.envoy.com/hub/docs/make-your-first-api-request) | Scoped read-only v1 location inventory sample; outputs counts, not addresses, visitor PII or an assertion about role assignments |
| Expiration Reminder | Customer tenant authentication, roles, credentials and audit | [Roles](https://help.expirationreminder.com/user-roles-access-privileges), [2FA/SSO incompatibility](https://help.expirationreminder.com/two-factor-authentication), [UI Audit Log](https://help.expirationreminder.com/audit-log), [REST event log](https://developers.expirationreminder.com/api-reference/event-log-get-all-event-logs) | Current endpoint reference uses `api.expirationreminder.com`, unlike the older .net Key Concepts example. Reads one page and emits counts, not personal data. Pack behavior does not limit bearer-key privileges |

All packs read documented first-party customer API resources. The printed aggregates are evidence aids and not control effectiveness verdicts. Production access and subscription entitlements were not validated.
