# Cursor Origin packs

Use the complete folder and the pinned native documentation. Origin is early beta; a repository's GitHub source, mirror and Origin grants are separate control planes.

The `api` Bash entrypoint needs Bun, its adjacent TypeScript helpers, and an existing `ORIGIN_APP_JWT`. GET-only pagination inventories installations of that authenticated app, not every app installed in an organization. JSON `status: REVIEW` with exit 0 means the read completed; it is not an approval of access. Missing authority, schema drift or transport failure returns JSON `status: UNKNOWN` with exit 3. Missing Bun exits 2. Raw response bodies and installation identities are suppressed; no JWT or installation token is minted.

The `cli` Bash entrypoints use an already installed official `origin` CLI. Set `HTH_ALLOW_READONLY=1` and a reviewed `ORIGIN_REPO=owner/repository`; the wrappers reject a custom `CURSOR_ORIGIN_ENDPOINT`. They do not install, authenticate or mutate. Their read output may contain repository names, identities and policy details; protect it as evidence. Repository and namespace reads both matter for inherited access.

The `terraform` folder pins the first-party `cursor/cursor` provider to `0.8.0`. Load its control files, `providers.tf` and `variables.tf` together. Existing repository/direct-grant data sources provide inventory; they do not prove effective access from every inheritance or app path. Optional IP/SSH posture reads are off by default. Resource management and restrictive enforcement require explicit opt-ins, and IP/SSH enforcement also requires a recovery-access attestation. That Boolean is not proof that a recovery test happened.

Ruleset lists replace managed lists; review existing conditions, bypass actors and required checks, then import the intended existing resources before management. Do not mix whole-set and per-entry IP ownership. The provider does not expose Origin's `trustAppDeclaredIps` bypass; verify that native REST field separately. IP rules exempt documented Cursor service traffic. SSH certificate policy blocks registered user keys and user API keys over HTTPS, not every installation-token or app path. Use only a reviewed CA public key; no private key or credential is generated. Deletion guards deliberately block removal and require an operator decision for lifecycle changes.

Terraform state and CLI output can expose policy/identity metadata. Configure existing provider authentication and protected state, and review a plan before applying. This refresh initialized and validated the provider with vendor credentials absent; no configure, plan, apply, import, app install or credential operation ran.
